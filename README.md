# Умный подбор подрядчиков (#79-lite)

Сервис помогает заказчику выбрать event-подрядчика из каталога своего города. Он принимает параметры заказа и возвращает **до трёх карточек**. В каждой карточке есть объяснение, почему этот подрядчик попал в выдачу. Объяснение собрано из фактов конкретного профиля: цитаты из описания, цены относительно бюджета, языка, часов на площадке и отличий от соседних карточек.

Главный принцип: не удлинить список, а помочь выбрать. Поэтому сервис честно говорит, когда подходящих меньше трёх или нет вовсе, и объясняет почему.

Запрос можно написать обычным текстом: «свадьба в Алматы 14 ноября, бюджет 500к, ведущий на казахском». **ИИ-агент** на OpenAI разберёт фразу, сам вызовет движок подбора, при пустом результате поищет на соседней дате и даст короткий совет. Каждое число в совете сверяется с данными, поэтому агент не может выдумать цену или дату.

**Репозиторий:** https://github.com/BAITC-Hacks/hack-7c6720cb-steppe-tech

---

## Что делает проект

1. Принимает запрос: город, дату, тип мероприятия, категорию подрядчика и бюджет в тенге. Длительность в часах и язык можно указать дополнительно.
2. Отбирает подрядчиков нужной категории в городе и отсекает тех, кто не проходит жёсткие условия. Это занятость на дату, формат мероприятия, бюджет, язык и максимум часов.
3. Ранжирует оставшихся детерминированной формулой и показывает не больше трёх.
4. Для каждой карточки пишет одно-два предложения объяснения из фактов профиля.
5. Явно различает три исхода:

| Исход | Код в API | Что видит пользователь |
|---|---|---|
| Подобрали | `found` | До трёх карточек. Если их меньше трёх, отдельной строкой сказано почему. |
| В этом городе такой категории нет | `no_category_in_city` | Текст о том, что категории нет, и в каких городах она есть. |
| Кандидаты есть, но ни один не проходит | `no_match` | Сколько кандидатов и по какой причине отсеян каждый, а также ближайшие свободные даты и нужный бюджет. |

Бронирования, заявок и уведомлений нет. Сервис только рекомендует.

## Что реализовано

Соответствие требованиям задачи:

| Требование | Как сделано |
|---|---|
| Вход: город, дата, тип, категория, бюджет, плюс длительность и язык по желанию | Запрос обычным текстом через ИИ-агента, веб-форма, JSON API и CLI. Даты принимаются как `2026-11-14` и как `14.11.2026`. Некорректный ввод получает понятный ответ, а не ошибку 500. |
| До трёх карточек с именем, категорией, городом, ценой и объяснением | `cards[]` в ответе API. Объяснение всегда содержит конкретную цену и долю бюджета. |
| Без общих фраз | Текст собирается только из фактов профиля. Общих шаблонов вроде «отличный выбор» в коде нет, и тест проверяет это. |
| Занятый на дату не попадает в выдачу, площадки с тем же календарём | Проверка занятости одинакова для всех категорий. «Банкетный зал» и «Отель» обрабатываются так же, как «Ведущий». |
| Меньше трёх: показать сколько есть и сказать почему | Поле `why_fewer` со счётчиками причин отсева. Плюс подсказка о соседних датах, где подходящих больше. |
| Детерминизм | В движке нет случайности и внешних вызовов. Сортировка идёт по баллу, затем по цене, затем по `id`. Профили загружаются в порядке `id`. ИИ-агент только выбирает параметры и пишет совет, а карточки всегда строит движок. |
| Три исхода различимы явно | Отдельный `outcome`, отдельная плашка в интерфейсе: синяя, белая или контурная. Отдельный текст. |
| Одна и та же выдача на две даты отличается, и видно, что дело в занятости | Поле `date_effect` называет профили, которые попали бы в подборку, но заняты именно в эту дату. У отсеянных указаны ближайшие свободные даты. |
| Видно, где настоящий профиль, а где синтетический | Бейдж на каждой карточке: «реальный профиль», «синтетический профиль» или «добавлен командой». Отдельные бейджи стоят, если город или цена проставлены при подготовке данных. |
| Три обязательных демо-запроса | Скрипт `scripts/demo.py` и кнопки-пресеты в интерфейсе. Сценарии подбираются автоматически под загруженный датасет. |
| Ответ быстрее 10 секунд | Подбор занимает меньше миллисекунды, HTTP-ответ несколько миллисекунд. |

Дополнительно:

- **ИИ-агент с проверкой фактов.** Понимает запрос обычным текстом, сам вызывает движок, ищет альтернативы и объясняет выбор. Подробности в разделе «ИИ-агент».
- **Прозрачный скоринг.** В каждой карточке видны итоговый балл и шкала по каждому компоненту с его весом.
- **Список отсеянных.** Для каждого отсеянного подрядчика указаны все причины отказа, а не только первая.
- **Подсказки при пустом результате.** Сервис ищет соседние даты, где кто-то подходит, и называет бюджет, при котором подошёл бы самый доступный свободный подрядчик.
- **Опечатка в категории.** Если такой категории нет нигде, сервис предлагает похожие названия.
- **Тесты.** 27 юнит-тестов: требования задачи, загрузка CSV из Excel и ИИ-агент с подменой модели, без сети и ключа.

## Технологии и архитектура

**Стек:** Python 3.10+ и только стандартная библиотека, pip-пакеты не нужны. ИИ-агент работает через OpenAI API, модель по умолчанию `gpt-5.4-mini`. Интерфейс написан одной HTML-страницей на чистом JavaScript.

### Структура

```
podbor/
  data.py        загрузка JSONL/CSV/XLSX, русские заголовки, нормализация полей
  xlsx.py        чтение .xlsx без внешних библиотек
  engine.py      пайплайн: валидация, фильтры, скоринг, объяснения, три исхода
  ai.py          ИИ-агент: разбор текста, вызов движка как инструмента, проверка фактов
  text.py        русские склонения, форматирование денег и дат
  scenarios.py   автоподбор демо-запросов под загруженные данные
  server.py      HTTP-сервер: страница и JSON API
  cli.py         командная строка
static/index.html  веб-интерфейс
static/favicon.svg иконка
scripts/demo.py    прогон всех обязательных сценариев
scripts/make_demo_data.py  генератор демо-датасета
tests/test_engine.py       тесты движка
tests/test_ai.py           тесты ИИ-агента
data/              датасеты
```

### Пайплайн

```
запрос
  │
  ├─ 1. Валидация и нормализация (регистр, ё→е, формат даты)
  │
  ├─ 2. Кандидаты: категория + город
  │      └─ пусто → исход «в этом городе такой категории нет»
  │                 (+ в каких городах категория есть, + похожие категории)
  │
  ├─ 3. Жёсткие фильтры для каждого кандидата, все причины сохраняются:
  │      занят на дату → не берёт формат → дороже бюджета → нет языка → мало часов
  │      └─ никто не прошёл → исход «кандидаты есть, но ни один не подходит»
  │                          (+ причина по каждому, свободные даты, нужный бюджет)
  │
  ├─ 4. Скоринг прошедших, сортировка (−балл, цена, id), топ-3
  │
  ├─ 5. Эффект даты: пересчёт топ-3 без учёта занятости.
  │      Кто вошёл бы, но занят, попадает в текст date_effect
  │
  └─ 6. Объяснение для каждой карточки с учётом двух других карточек
```

### Скоринг

Балл нужен только для порядка карточек. Все жёсткие условия уже проверены на шаге 3.

| Компонент | Вес | Как считается |
|---|---|---|
| Смысл описания и специализация | 35% | Есть ли в описании предложение про запрошенный формат. Ищем по основам слов: для тоя это «той», «узату», «беташар», «сундет» и так далее. Бонус за узкую специализацию, если подрядчик берёт не больше двух-трёх форматов. |
| Запас по бюджету | 30% | Цена до 70% бюджета даёт максимум. Дальше балл линейно снижается до 0.5 на границе бюджета. |
| Язык | 15% | Если язык запрошен, выше тот, у кого он подтверждён ещё и в описании. Для тоя и свадьбы без указанного языка плюс за казахский. |
| Часы на площадке | 10% | Запас часов сверх запрошенной длительности. |
| Надёжность данных | 10% | Реальный профиль весит 1.0, профиль с проставленным городом или ценой 0.85, синтетический 0.7. |

### Как строится объяснение

Для карточки собирается список фактов с приоритетами:

- **Цитата из описания** про запрошенный формат. Если такая же цитата есть у соседней карточки, её приоритет снижается, потому что она не различает карточки.
- **Честная оговорка**, если формат заявлен в профиле, но в описании о нём не сказано.
- **Узкая специализация**, например «берёт только свадьбы и юбилеи».
- **Язык**, в том числе «единственный такой среди подобранных».
- **Часы на площадке** относительно запрошенной длительности.
- **Опыт** из описания, например «опыт 8 лет» или «с 2015 года».
- **Бюджет**, он есть всегда: цена, доля бюджета и сравнение с соседями, например «самый доступный из подобранных».

Первое предложение строится из самого сильного отличительного факта. Второе содержит бюджет и ещё один факт, если он достаточно весомый. Сравнительные формулировки считаются относительно двух других карточек. Поэтому без имён карточки одного запроса нельзя перепутать.

## ИИ-агент

Агент — это LLM, которой движок подбора выдан как инструмент. Модель понимает человеческий запрос и решает, какие поиски сделать. Отбор, ранжирование и объяснения в карточках остаются за детерминированным движком.

```
текст пользователя
  │
  ├─ 1. LLM извлекает параметры. JSON-схема инструмента перечисляет допустимые
  │      города, категории, форматы и языки, поэтому выдумать их нельзя.
  │      Не хватает данных → агент задаёт один уточняющий вопрос.
  │
  ├─ 2. Вызов search_vendors = recommend() из engine.py
  │
  ├─ 3. Никто не подошёл или меньше трёх → агент сам делает ещё 1–2 поиска,
  │      меняя один параметр по подсказкам движка: соседняя дата или бюджет
  │
  ├─ 4. LLM пишет совет из 2–4 предложений по ответам инструмента
  │
  └─ 5. Проверка фактов: каждое число в совете должно встречаться в запросе
         или в ответах движка. Не сошлось → показываем текст движка
```

В интерфейсе видны совет агента, отметка о проверке фактов и каждый шаг агента с параметрами поиска. Альтернативный поиск можно открыть кнопкой «Показать».

**Почему агент поверх правил, а не вместо них:**

1. **Детерминизм.** Карточки и их порядок на один и тот же набор параметров всегда одинаковы. От модели зависит только разбор текста и формулировка совета.
2. **Нет галлюцинаций в фактах.** Модель не видит сырой каталог и не может добавить подрядчика. Числа в совете проверяются кодом.
3. **Работает без ИИ.** Без ключа форма, API и CLI работают как раньше, а на странице видно, что ИИ выключен.

Дообучение на 66 записях задача прямо не рекомендует, и мы его не делали.

### Как включить

Создайте в корне проекта файл `.env` с ключом. Файл уже в `.gitignore`, в репозиторий он не попадёт.

```
OPENAI_API_KEY=sk-...
OPENAI_MODEL=gpt-5.4-mini
```

Вместо файла можно задать переменные окружения. Строка `OPENAI_MODEL` необязательна.

Проверка из командной строки:

```bash
python -m podbor.ai "той 5 декабря в Алматы, нужен флорист, бюджет 250 тысяч"
```

Пример вывода:

```
Шаг 1: search_vendors({"city": "Алматы", "date": "2026-12-05", "event_format": "той", "category": "Флорист", "budget": 250000}) → Кандидаты есть, но ни один не проходит по условиям
Шаг 2: search_vendors({"city": "Алматы", "date": "2026-12-01", "event_format": "той", "category": "Флорист", "budget": 250000}) → Подобрали
...
Совет ИИ (проверен):
Советуем Тихиро Огино: он доступен на 01.12.2026 и укладывается в бюджет от 250 000 ₸. ...
```

Один запрос к агенту занимает 2–7 секунд, это укладывается в лимит задачи в 10 секунд.

## Установка и запуск

Нужен Python 3.10 или новее. Устанавливать пакеты не нужно.

```bash
git clone https://github.com/BAITC-Hacks/hack-7c6720cb-steppe-tech.git
cd hack-7c6720cb-steppe-tech
```

Для ИИ-агента положите ключ OpenAI в файл `.env`, как описано в разделе «ИИ-агент». Без ключа всё остальное работает.

**Данные.** Положите файл с базой в папку `data/`. Подходят форматы CSV, XLSX и JSONL, имя файла любое.

Если файлов несколько, порядок выбора такой:

1. Путь из переменной окружения `PODBOR_DATA`.
2. Файл `hackathon-dataset-anonymized` с расширением `.jsonl`, `.csv` или `.xlsx`.
3. Любой другой файл данных в `data/`, первый по алфавиту. Так подхватывается датасет хакатона `data/hackathon dataset anonymized .csv`, который лежит в репозитории.
4. Демо-набор `data/demo-dataset.jsonl`, если своих файлов нет.

Какой файл загружен, сервер пишет при старте. Это же видно внизу веб-страницы.

Демо-набор уже лежит в репозитории. Пересоздать его можно так:

```bash
python scripts/make_demo_data.py
```

**Веб-интерфейс и API:**

```bash
python -m podbor.server
# Откройте http://127.0.0.1:8000
```

Открывайте именно `127.0.0.1`, а не `localhost`. На Windows `localhost` сначала пробует IPv6, и каждый запрос ждёт около двух секунд.

Ссылка вида `http://127.0.0.1:8000/#s1` сразу запускает первый готовый сценарий, `#s2` второй и так далее. Ссылка `http://127.0.0.1:8000/#ask=текст запроса` сразу отправляет текст ИИ-агенту. Это удобно для показа.

Порт и адрес меняются флагами `--port` и `--host` или переменными `PORT` и `HOST`.

**Командная строка:**

```bash
python -m podbor.cli --city Алматы --date 2026-11-14 --format свадьба --category Ведущий --budget 500000
python -m podbor.cli --city Алматы --date 14.11.2026 --format той --category "Банкетный зал" --budget 3000000 --hours 8 --language казахский
python -m podbor.cli ... --json      # сырой ответ API
```

За рубежом в каталоге нет подрядчиков категории «Флорист». Эта категория есть в других городах (Алматы: 2, Астана: 1).

5. Кандидаты есть, но никто не подходит: Флорист, Алматы
[Кандидаты есть, но ни один не проходит по условиям]
В Алматы есть 2 подрядчика категории «Флорист», но ни один не подходит: 2 заняты 05.12.
  Почему не подошли:
   - Нурлан Д.: занят 05.12, ближайшие свободные даты: 30.11 (пн), 10.12 (чт)
   - Руслан Т.: занят 05.12, ближайшие свободные даты: 30.11 (пн), 08.12 (вт)
  Подсказка: Соседние даты, где кто-то подходит по всем условиям: 30.11 (пн): подходят 2; 08.12 (вт): подходит 1; 10.12 (чт): подходят 2.

Скрипт подбирает сценарии заново под загруженный файл, поэтому на любом датасете он показывает все пять исходов.

Эндпоинты:

| Метод и путь | Назначение |
|---|---|
| `POST /api/recommend` | Подбор, параметры в JSON |

|---|---|

### Тесты

```bash
python -m unittest discover -s tests -v
```

Тесты проверяют все три исхода и отсев занятых, в том числе в категории площадок. Ещё они проверяют жёсткие фильтры, детерминизм, различимость объяснений, отсутствие общих фраз и изменение выдачи при смене даты.

Тесты агента подменяют модель заранее записанными ответами. Они проверяют, что карточки берутся из движка, что совет с выдуманным числом заменяется текстом движка, что альтернативный поиск помечается для модели, что агент задаёт уточняющий вопрос и соблюдает лимит поисков. Сеть и ключ для тестов не нужны.

## Данные и внешние сервисы

**Внешний сервис один: OpenAI API** для ИИ-агента. Движок, форма, API подбора и CLI в сеть не ходят и работают без ключа. Агенту отправляются текст запроса и сжатые ответы движка: имена из каталога, цены и причины отсева.

**Данные:**

- **Ваша база или датасет хакатона** в формате CSV, XLSX или JSONL. Файл нужно положить в `data/`. Если закоммитить его в репозиторий, жюри воспроизведёт выдачу на настоящих данных.
- **`data/demo-dataset.jsonl`** — наш демо-набор на 66 профилей в том же формате. Он создан скриптом `scripts/make_demo_data.py` с фиксированным seed. Все профили помечены `synthetic: true`, имена вымышлены. Распределение категорий повторяет описанное в задаче: 15 ведущих, 12 фотографов, 8 банкетных залов и по 3 профиля в редких категориях. Загрузка календарей тоже как в задаче: 30–50% дней в сентябре–ноябре и 70–80% в декабре, выходные плотнее.
- **`data/extra-synthetic.jsonl`** — необязательный файл для своих синтетических профилей, которыми можно дополнить настоящий датасет. Если он есть, профили подмешиваются автоматически и получают бейдж «добавлен командой».

### Как подготовить свою таблицу

Первая строка таблицы должна содержать заголовки. Подходят имена полей из датасета или русские названия:

| Поле | Русский заголовок | Обязательно | Пример значения |
|---|---|---|---|
| `id` | ID, № | нет, пронумеруем сами | `42` |
| `anon_name` | Название, Имя, Подрядчик | да | `Арман Н.` |
| `categories` | Категория, Категории | да | `Ведущий` или `Фотограф, Видеограф` |
| `city` | Город | да | `Алматы` |
| `price_from_kzt` | Цена от, Цена, Стоимость | да | `190000` или `190 000` |
| `event_formats` | Форматы, Тип мероприятия | да | `свадьба, той, юбилей` |
| `languages` | Языки, Язык | да | `русский, казахский` |
| `max_hours` | Макс часов, Часы | нет | `6`, пусто для флористов и декораторов |
| `busy_dates` | Занятые даты, Занятость | да | `14.11.2026, 15.11.2026` |
| `description` | Описание | желательно | свободный текст |
| `synthetic` | Синтетический | нет | `ИСТИНА` или `ЛОЖЬ`, `да` или `нет` |

Списки внутри ячейки разделяются запятой, точкой с запятой или переносом строки. Даты принимаются в видах `14.11.2026`, `2026-11-14` и как ячейка-дата Excel. Если обязательного столбца нет, сервис при запуске назовёт, каких столбцов не хватает и какие заголовки он нашёл.

**CSV из Excel.** Сохраняйте таблицу через «Файл → Сохранить как → CSV UTF-8 (разделитель — запятая)». Обычный вариант «CSV (разделители — запятые)» тоже читается, но он сохраняет в кодировке Windows-1251. В ней нет казахских букв ә, ө, ұ, ү, қ, ғ, ң, һ, і, и Excel заменит их знаками вопроса. Разделитель «;», который ставит русский Excel, определяется автоматически.

Старый формат `.xls` не поддерживается. Пересохраните такой файл как `.xlsx` или CSV UTF-8.

## Известные ограничения

- **Совет ИИ проверяется только по числам.** Имена и формулировки модель берёт из ответов движка, но код их не сверяет. Структура ответа это ограничивает: модель видит только результаты поиска.
- **Ответ агента зависит от модели.** Параметры и совет на одинаковый текст могут слегка отличаться между запусками. Карточки на одни и те же параметры всегда одинаковы.
- **Смысловое совпадение в описаниях ищется по словарю основ слов.** Это надёжно для шести форматов из задачи, но не ловит перефразирования вне словаря. Например, «проводим проводы невесты» без слова «узату» найдено не будет. ИИ-агент понимает перефразирования в запросе пользователя, но не в описаниях подрядчиков.
- **Веса скоринга подобраны вручную.** Размеченных данных о том, кого заказчики выбирают на самом деле, нет.
- **Бюджет трактуется как бюджет на одного подрядчика этой категории.** Сравнивается только цена «от». Фактическая цена может оказаться выше, поэтому запас по бюджету поднимает подрядчика выше в выдаче.
- **Профили без цены, форматов или языков не отсекаются.** Этот пробел отражается в тексте карточки и снижает балл.
- **Календарь известен только с 23.09.2026 по 31.12.2026.** Для дат вне окна сервис предупреждает, что занятость неизвестна.
- **Склонения захардкожены.** Для городов, форматов и языков из задачи формы прописаны явно. Для нового города текст будет корректным, но более казённым: «в городе X».
- **Демо-описания шаблонные.** Они сгенерированы из фраз, поэтому объяснения на демо-наборе выглядят однообразнее, чем будут на настоящих описаниях.

### Куда развивать

- **Эмбеддинги для смыслового совпадения.** Готовая мультиязычная модель заменит или дополнит словарь основ. Векторы описаний считаются один раз при загрузке, и детерминизм сохраняется.
- **Разметка описаний через LLM.** Один раз при загрузке модель отмечает, какие форматы и услуги упомянуты в каждом описании. Результат кешируется, поэтому выдача остаётся детерминированной.
- **Диалог с агентом.** Уточнения вроде «а если на день позже» или «покажи подешевле» поверх уже сделанного подбора.
- **Обратная связь.** Логировать, кого заказчик выбрал из тройки, и подбирать веса по этим данным.
- **Мультикатегорийные запросы.** Например, «ведущий и фотограф на одну дату» с подбором согласованных пар.
